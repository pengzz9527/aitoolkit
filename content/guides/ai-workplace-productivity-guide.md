## 一、邮件处理：从"每天2小时"到"20分钟搞定"

职场人平均每天花1.5-2小时处理邮件，其中80%是同类回复（确认收到、安排会议、发送资料）。AI可以批量完成这些工作。

### 1.1 快速起草回复邮件

收到一封需要回复的邮件，直接转发给AI：

> **提示词：**
> ```
> 请帮我起草一封商务回复邮件。以下是对方发来的邮件内容：
> 
> [粘贴邮件原文]
> 
> 我的背景信息：
> - 我的职位：[你的职位]
> - 对方身份：[对方职位/公司]
> - 我的立场/态度：[同意/拒绝/需要协商/仅确认收到等]
> - 关键回应要点：[你希望传达的核心内容]
> 
> 要求：语气专业但友好，字数150字以内，直接可用，不要寒暄套话。
> ```

如果一天有10封邮件要回，AI可以用5分钟全部起草完毕，你只需要逐一审视修改。

### 1.2 批量分类和优先级排序

当你有一堆邮件堆积时，让AI帮你梳理：

> **提示词：**
> ```
> 以下是我今天收到的5封工作邮件，请帮我：
> 1. 按紧急程度排序（P0必须今天处理 / P1本周处理 / P2可延后）
> 2. 每封邮件提取核心诉求（一句话总结）
> 3. 对P0级别的邮件直接起草回复草稿
> 4. 标注哪些邮件需要我亲自处理，哪些可以直接转交他人
> 
> 邮件列表：
> [粘贴邮件标题+摘要]
> ```

### 1.3 邮件语气调整

写好的邮件总觉得不够得体？让AI帮你润色：

> **提示词：**
> ```
> 帮我改写以下邮件，要求：
> - 语气：[更委婉/更强势/更正式/更简洁]
> - 目标读者：[老板/客户/同事/下属]
> - 保留的核心信息：[列出不能删除的内容]
> 
> 原文：
> [粘贴你的草稿]
> ```

## 二、周报/月报撰写：3分钟出初稿

周报是最容易被拖延的工作之一——因为每次都要从空白文档开始。用AI，你可以彻底改变这个习惯。

### 2.1 碎片化输入法

不需要整理好素材再问AI。每天把零散的工作记录丢进去：

> **提示词：**
> ```
> 以下是我本周的工作碎片记录，请帮我整理成一份结构化的周报，用于发送给直属领导。
> 
> 本周记录：
> - 周一：开了产品评审会，确认了Q3功能规划
> - 周二：完成了用户反馈数据的初步整理，发现3个高频问题
> - 周三：写了PRD文档v2，并发给开发团队
> - 周四：修复了线上bug #2847
> - 周五：协助新同事熟悉项目代码
> - （其他零散事项...）
> 
> 要求：
> 1. 按"本周完成/下周计划/风险与阻塞"三部分组织
> 2. 成果部分要有量化数据（如果没有数据就注明待补充）
> 3. 语气专业简洁，每部分控制在3-5条
> 4. 适当突出个人贡献，但不要过度夸大
> ```

### 2.2 月度汇报升级

月报比周报更复杂，涉及跨周的数据汇总。结合AI和[CSV SQL Analyzer](https://198007.xyz/tools/csv-sql-analyzer/)可以大幅提升效率：

> **提示词：**
> ```
> 以下是我本月的工作数据（CSV格式），请帮我生成月度汇报要点：
> 
> [粘贴或上传CSV数据]
> 
> 要求：
> 1. 提取关键指标的变化趋势（环比/同比）
> 2. 识别异常数据点并分析可能原因
> 3. 生成3个核心结论，每个结论配1个数据支撑
> 4. 用表格呈现主要指标对比
> ```

> 💡 **进阶技巧：** 如果你的月度数据是表格形式，先把CSV整理好，用 [CSV SQL Analyzer](https://198007.xyz/tools/csv-sql-analyzer/) 做初步分析，再把分析结果喂给AI写文字总结——这样生成的报告既有数据支撑又有文字阐述。

### 2.3 季度OKR复盘

> **提示词：**
> ```
> 以下是我本季度的OKR目标和实际完成情况，请帮我做一份复盘报告：
> 
> 【O1：提升产品用户留存率】
> - KR1： DAU从10万提升到15万 → 实际达成13.5万（87%）
> - KR2： 新用户7日留存从25%提升到35% → 实际达成32%（91%）
> 
> 【O2：完成技术架构升级】
> - KR1： 微服务拆分完成80% → 实际完成65%
> - KR2： API响应时间降低30% → 实际降低22%
> 
> 要求：
> 1. 客观评估每个KR的完成质量（超额/达标/未达标）
> 2. 分析未达标项的根本原因（不要找借口，要找到可改进的切入点）
> 3. 给出下季度O/KR的建议方向
> 4. 格式适合直接粘贴到OKR系统
> ```

## 三、数据分析：不会SQL也能做分析

职场中很多数据需求不需要写代码——AI+在线工具就能搞定。

### 3.1 用自然语言描述你的分析需求

> **提示词：**
> ```
> 我有一份销售数据，包含以下字段：订单日期、客户地区、产品类别、销售额、利润率。
> 
> 请帮我回答以下问题，并写出对应的SQL查询语句（假设表名为 sales_data）：
> 1. 上季度各产品类别的销售趋势如何？
> 2. 哪个地区的利润率最高？为什么？
> 3. 找出销售额超过均值2倍以上的异常订单
> 4. 本月vs上月的销售额环比变化
> 
> 输出格式：每个问题一段分析结论 + 一段SQL代码
> ```

### 3.2 在浏览器中直接运行SQL

把AI生成的SQL粘贴到 [CSV SQL Analyzer](https://198007.xyz/tools/csv-sql-analyzer/) 中，上传你的CSV文件，直接执行查询并获得结果——不需要安装任何数据库软件。

### 3.3 让AI帮你解读分析结果

跑出数据后，别让数字躺在表格里。给AI一个明确的解读指令：

> **提示词：**
> ```
> 以下是数据分析的结果，请帮我写一段业务解读，用于向非技术背景的领导和客户汇报：
> 
> 数据结论：
> 1. Q3销售额同比增长18%，但Q3环比下降5%
> 2. 华东地区贡献了42%的销售额，但利润率最低（8%）
> 3. 高端产品线（>5000元）的退货率是大众产品线的3倍
> 
> 要求：
> - 先讲结论，再给原因分析
> - 指出3个 actionable 的业务建议
> - 避免专业术语，让没接触过数据的读者也能看懂
> - 控制在300字以内
> ```

## 四、PPT/演示文稿：从大纲到内容一步到位

做PPT最耗时的不是排版——是写内容。AI可以帮你快速生成结构完整的大纲和内容。

### 4.1 生成演示文稿大纲

> **提示词：**
> ```
> 我要做一个关于"[主题]"的汇报PPT，面向[受众]，时长[20/30/45]分钟。
> 
> 请帮我：
> 1. 设计完整的PPT结构（每页的标题和核心内容要点）
> 2. 标明哪些页面适合放数据图表，哪些适合放文字阐述
> 3. 给每页建议的视觉风格（数据型/故事型/对比型）
> 4. 预估总页数，控制在合理范围内
> 
> 背景信息：
> [简要描述汇报的背景和目的]
> ```

### 4.2 逐页生成内容

拿到大纲后，逐页让AI生成具体内容：

> **提示词：**
> ```
> 请帮我写PPT第3页的内容："[页面标题]"
> 
> 要求：
> - 3-5个要点，每个要点不超过20字
> - 适合放在PPT上展示（不是演讲稿）
> - 附带一段演讲备注（50-80字，用于现场讲解）
> - 建议配什么类型的图表或图片
> ```

### 4.3 合并整理成完整脚本

把所有页面的内容发给AI做一次整体润色：

> **提示词：**
> ```
> 以下是PPT的完整内容大纲和每页文案，请帮我：
> 1. 检查逻辑是否连贯（前页和后页是否有过渡）
> 2. 统一整体语气风格
> 3. 在关键页面之间添加过渡语
> 4. 给出开场白（30秒）和结束语（20秒）
> ```

## 五、会议管理：从"会前准备"到"会后跟进"全覆盖

### 5.1 会前：快速了解议题背景

> **提示词：**
> ```
> 我要参加一个关于[会议主题]的会议，请帮我：
> 1. 梳理这个话题的关键背景信息（3-5条）
> 2. 预测会议中可能被讨论的3个核心问题
> 3. 为每个问题准备我的观点和论据
> 4. 列出我应该向对方提问的2个问题
> 
> 背景信息：[粘贴相关文档或说明]
> ```

### 5.2 会中：实时记录整理

把会议中的语音转录文字或速记发给AI：

> **提示词：**
> ```
> 以下是会议记录（可能是语音转录，比较零散），请帮我整理成结构化的会议纪要：
> 
> 要求格式：
> 1. 会议基本信息（时间、参会人、主题）
> 2. 核心决议事项（逐条列出，标注决策人）
> 3. 待办事项（负责人+截止时间）
> 4. 后续跟进计划
> 5. 需要我特别注意的风险点
> ```

### 5.3 会后：自动生成跟进邮件

> **提示词：**
> ```
> 根据以上会议纪要，帮我起草一封跟进邮件，发送给所有参会者。
> 
> 邮件要求：
> - 开头简要说明会议成果
> - 列出双方确认的待办事项及责任人
> - 注明下次会议的时间/议题（如有）
> - 语气正式但不生硬
> - 中文，200字左右
> ```

## 六、方案设计与文档撰写

无论是技术方案、项目方案还是商业计划书，AI都能帮你快速搭出初稿框架。

### 6.1 技术方案设计

> **提示词：**
> ```
> 我需要设计一个[系统名称]的技术方案，背景是：
> - 业务场景：[描述]
> - 用户规模：[预估]
> - 技术约束：[比如必须用Python/需要兼容现有系统]
> 
> 请帮我：
> 1. 列出系统的核心模块和技术选型建议
> 2. 画一个简化的架构图（用文字描述）
> 3. 识别3个最大的技术风险及应对策略
> 4. 给出大致的实施时间线（分阶段）
> ```

> 💡 更多关于技术方案设计的详细内容，可以参考 [AI做技术方案设计指南](/guides/ai-tech-design-guide/)，里面涵盖了从需求分析到架构图绘制的完整流程。

### 6.2 文档格式规范化

写好的文档格式乱七八糟？用AI做格式清洗：

> **提示词：**
> ```
> 请帮我把以下文档内容格式化为标准的Markdown格式：
> - 标题层级清晰（H1/H2/H3）
> - 列表项统一格式
> - 关键结论用 **加粗** 标注
> - 代码块用 ``` 包裹
> - 移除多余的空行
> 
> 原文：
> [粘贴你的文档]
> ```

## 八、避免AI办公的三个常见陷阱

### 陷阱1：把AI输出直接复制提交

AI的初稿质量通常有60-70分，直接提交意味着你把最后30分的精细工作推给了你自己。**正确的做法是：让AI做"草稿生成器"，你做"主编"。** 逐条检查数据准确性、逻辑连贯性和语气恰当性。

### 陷阱2：提示词过于笼统

"帮我写周报"和"帮我写一份面向总监的月度工作汇报，突出Q3用户增长指标，语气正式简洁，包含数据支撑和风险提示"——这两个提示词输出的质量天差地别。**给你的AI一个明确的"角色+场景+要求"框架，输出质量直接翻倍。**

### 陷阱3：过度依赖单一工具

不同AI工具有不同的优势——ChatGPT擅长创意写作和快速响应，Claude擅长长文档和逻辑分析，GPT-4o擅长多模态理解。**根据任务类型选择最合适的工具，而不是所有事都交给同一个AI。**
