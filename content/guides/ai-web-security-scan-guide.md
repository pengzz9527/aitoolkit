## 一、为什么普通站长需要做安全扫描？

很多网站被攻击，不是因为黑客技术多强，而是因为**基础防护没做好**：

- 端口暴露：数据库端口（3306）、Redis 端口（6379）直接对外开放
- SSL 证书过期：浏览器显示"不安全"，用户不敢访问
- 目录遍历：`/admin/`、`/backup/` 等敏感目录公开可访问
- 信息泄露：服务器版本、框架名称直接暴露在响应头中

这些问题的排查成本极低——用 AI 辅助，10 分钟就能完成一次完整的基础扫描。

## 二、第一步：用 ChatGPT 帮你写端口扫描命令

端口扫描是安全检查的第一步。你需要知道服务器上哪些端口对外开放了。

### 方法 A：本地扫描你的服务器

如果你的服务器在 Linux 上，打开终端，对 ChatGPT 说：

> **指令模板：**
> "我有一台 Linux 服务器，IP 地址是 [你的IP]。请帮我写一个端口扫描命令，检查常见的 Web 相关端口（80、443、8080、8443、3306、5432、6379、22），并告诉我每个端口的含义。"

ChatGPT 会给你类似这样的命令：

```bash
for port in 22 80 443 3306 5432 6379 8080 8443; do
  (echo > /dev/tcp/你的IP/$port) 2>/dev/null && echo "端口 $port 已开放" || echo "端口 $port 关闭"
done
```

**关键判断标准：**

| 端口 | 应该开放吗？ | 说明 |
|------|-------------|------|
| 22 | ✅ 可以 | SSH 远程管理，但建议改默认端口 |
| 80 | ✅ 必须 | HTTP 网页服务 |
| 443 | ✅ 必须 | HTTPS 加密网页服务 |
| 3306 | ❌ 不应该 | MySQL 数据库，绝不能对外暴露 |
| 5432 | ❌ 不应该 | PostgreSQL 数据库，绝不能对外暴露 |
| 6379 | ❌ 不应该 | Redis 缓存，绝不能对外暴露 |
| 8080 | ⚠️ 看情况 | 备用 Web 端口，确认用途后决定是否关闭 |

如果 3306、5432、6379 这些端口开放了，说明你的数据库或缓存服务**直接暴露在公网**，需要立即修复。

## 三、第二步：用 AI 检查 SSL 证书状态

SSL 证书过期是站长最容易忽略的问题。证书一旦过期，所有访问者都会看到"不安全"警告。

### 手动检查

对 ChatGPT 说：

> **指令模板：**
> "我的网站域名是 [你的域名]，请告诉我怎么检查它的 SSL 证书是否有效、何时到期，以及证书链是否完整。"

ChatGPT 会教你用 OpenSSL 命令：

```bash
echo | openssl s_client -servername 你的域名.com -connect 你的域名.com:443 2>/dev/null | openssl x509 -noout -dates -subject
```

输出结果中：
- `notBefore`：证书开始生效日期
- `notAfter`：证书到期日期
- `subject`：证书颁发给的域名

### 自动提醒设置

让 ChatGPT 帮你写一个自动检查脚本：

> **指令模板：**
> "请帮我写一个 Shell 脚本，每天检查 [你的域名] 的 SSL 证书还剩多少天到期。如果少于 30 天，就发送一条通知消息。脚本要能放在 crontab 里每天运行一次。"

ChatGPT 会给你一个完整的脚本，包含证书解析、天数计算和通知逻辑。你只需要把通知方式改成你喜欢的渠道（邮件、钉钉、微信等）。

## 四、第三步：用 AI 排查常见配置漏洞

除了端口和证书，还有一些常见的配置问题会暴露你的网站。

### 检查响应头信息泄露

> **指令模板：**
> "请帮我写一段命令，检查 [你的域名] 的 HTTP 响应头，看看有没有暴露服务器类型、版本号等敏感信息。如果有，告诉我怎么修复。"

ChatGPT 会教你用 curl 查看响应头：

```bash
curl -I https://你的域名.com
```

重点关注这些字段：
- `Server`：可能暴露 Nginx/Apache 版本
- `X-Powered-By`：可能暴露 PHP/Node.js 版本
- `X-AspNet-Version`：如果是 .NET 站点会暴露

如果这些信息泄露了，ChatGPT 会告诉你对应的配置文件该怎么改。比如 Nginx 里加一行 `server_tokens off;` 就能隐藏版本号。

### 检查敏感目录

> **指令模板：**
> "我有一个网站 [你的域名]，请帮我列出常见的敏感目录列表，并教我怎么用简单的脚本批量检测这些目录是否存在。"

ChatGPT 会给你一个敏感目录清单（如 `/admin`、`/backup`、`/.git`、`/wp-admin`、`/phpmyadmin`）和批量检测脚本。如果发现某个敏感目录存在，立即删除或限制访问。

### 检查数据库连接配置

如果你的网站涉及数据存储，让 ChatGPT 帮你检查数据库配置：

> **指令模板：**
> "我用的是 [MySQL/PostgreSQL/MongoDB]，请给我一份安全检查清单，列出最常见的数据库配置错误和修复方法。"

ChatGPT 会给你一份定制化的清单，包括：禁用远程 root 登录、修改默认端口、设置强密码、启用日志审计等。

## 五、进阶：用 AI 做数据驱动的安全分析

如果你的网站有一定规模，会产生大量的访问日志。手动分析日志太痛苦，但用 AI 就很简单。

### 日志分析三步走

1. **导出日志**：把 Nginx/Apache 的 access.log 下载下来
2. **交给 ChatGPT 分析**：

> **指令模板：**
> "这是我的网站访问日志片段，请帮我分析：1）最近有哪些异常请求？2）有没有 SQL 注入或 XSS 攻击的痕迹？3）哪些 IP 访问频率最高？"

3. **用工具深入分析**：如果日志量很大（比如超过 10 万行），建议先用 [198007.xyz 的 CSV-SQL 分析工具](/tools/csv-sql-analyzer/) 将日志转为结构化表格，然后用 SQL 查询筛选异常数据。对于更复杂的数据分析场景，也可以参考 [DuckDB](https://duckdb.org/zh/) 的文档，用 SQL 高效处理大规模日志文件。

## 六、安全扫描检查清单

把下面这份清单收藏起来，每月执行一次：

- [ ] 端口扫描：确认只有必要的端口对外开放
- [ ] SSL 证书：检查有效期，提前 30 天续费
- [ ] 响应头：确认没有泄露服务器版本信息
- [ ] 敏感目录：确认 `/admin`、`/.git`、`/backup` 等不可访问
- [ ] 访问日志：检查是否有异常请求模式
- [ ] 数据库：确认没有远程直连风险
- [ ] 备份：确认有最近的可用备份
