## 先把「网页转 Markdown」这件事说透

收藏的网页过两周就找不到了，PDF 论文正文选不中、复制出来全是乱码，电子书各平台格式互不通用，想离线读还得一个个转……这些「读不完、找不着、存不住」的问题，根源都一样：**内容锁在别人平台的格式里**。

Markdown 是目前最通用的「中间格式」：纯文本、任何设备能打开、方便全文搜索、方便丢进笔记软件或 AI 对话里喂给它。把网页、PDF、电子书统一转成 Markdown，再集中存到一个文件夹里，你就有了一个**不依赖任何平台、随时能搜、随时能用 AI 提问的离线知识库**。

这套流程的核心就四步：**收集 → 转换 → 存库 → 检索**。全程不需要写代码，AI 负责最脏最累的「清洗」部分，你只负责下指令。

---

## 一、第一步：收集——先把原料攒起来

别一上来就动手转换。先把要转的内容攒成三类「原料」：

| 原料 | 常见形态 | 保存建议 |
|------|----------|----------|
| 网页文章 | 长文、教程、技术博客 | 用浏览器直接保存网页，或复制正文 |
| PDF 文档 | 论文、说明书、报告 | 原文件保留，记下标题和页数 |
| 电子书 | EPUB、MOBI、AZW3 | 原文件保留，统一放进一个文件夹 |

**关键动作**：建一个文件夹 `~/knowledge/raw/`，按「主题/日期」命名子文件夹，把原料丢进去。不要追求一步到位，先攒够 10-20 篇再批量处理，效率最高。

---

## 二、第二步：转换——让 AI 做最脏的活

这是全文最核心的一步。三种原料，三种打法。

### 场景 A：网页文章 → 干净的 Markdown

网页里 80% 的篇幅是导航栏、广告、侧边栏、「相关文章」推荐。直接复制粘贴进笔记里，读起来像被塞了一堆广告。让 AI 帮你过滤：

把网页正文复制下来（包括广告也无所谓），粘给 ChatGPT：

> **提示词：**
> ```
> 下面是一篇网页文章的原始内容，其中混有导航栏、广告、侧边栏、推荐阅读等噪音。请：
> 1. 只保留正文，删掉所有广告和导航内容
> 2. 把标题层级整理成 Markdown 的 # ## ### 结构
> 3. 正文里的图片用 ![描述](原始URL) 的形式保留
> 4. 表格转成 Markdown 表格
> 5. 文章开头加一行：来源：<原文URL>
> 6. 直接输出完整 Markdown，不要任何解释
> ```
> （然后粘贴网页正文）

你会拿到一份干净、带来源、带层级的 Markdown，直接保存成 `文章标题.md` 就行。

**批量场景**：如果一次要转 30 篇，把网页正文存成一个个 txt 文件，让 ChatGPT 写个脚本一次性处理：

> "写一个 Python 脚本：读取 ./raw/web/ 目录下所有 txt 文件，调用 LLM API 把每篇清洗成 Markdown 并输出到 ./knowledge/md/，文件名保持和源文件一致。每处理完一个打印文件名，方便我确认。"

脚本跑完，30 篇干净文章就进库了。你写脚本的过程也完全可以交给 AI，自己只管看输出对不对。

### 场景 B：PDF 论文/报告 → 可搜索的 Markdown

PDF 最大的坑是「正文选不中」——尤其是双栏排版的论文，复制出来左右两栏的文字会互相穿插，完全没法读。AI 在这里的价值是「重组阅读顺序」：

1. 把 PDF 直接丢给 ChatGPT（现在主流模型都支持读 PDF 附件），它会自动按正确顺序抽取正文。
2. 关键指令——让它「按论文结构」而不是「按版面」输出：

> **提示词：**
> ```
> 这是一篇 PDF 论文，请按以下结构输出 Markdown：
> # 标题
> ## 摘要
> ## 1. 引言
> ## 2. 方法
> （按原文章节走，双栏排版请按正确阅读顺序合并，不要把左右栏文字交错）
> 公式用 LaTeX 格式（$...$）保留
> 图表用 ![图1描述](描述) 占位，并标注原文页码
> 最后加一个「引用信息」小节，列出作者、发表年份、来源
> ```

如果论文里的公式很多，追加一句「公式必须转成可编译的 LaTeX，不要写成图片描述」。

**页数多的大报告（100+ 页）**：不要一次全丢，按章节拆成 2-3 次处理，最后手动拼接，比硬塞一整个文件成功率高得多。

### 场景 C：电子书 → 全书 Markdown

EPUB 这类格式本身就有结构（目录、章节），转成 Markdown 其实很机械，AI 主要帮你「统一格式」：

> "这是从 EPUB 里提取出来的全书纯文本（章节之间用三个换行分隔）。请：1. 把每个章节标题识别成 `## 第X章 标题`；2. 正文段落之间保留一个空行；3. 去掉出版社水印、页眉页脚；4. 输出完整 Markdown。"

一次转一章最稳。整本书几十章，配合上面那种批量脚本思路，可以让 AI 写个循环脚本一次跑完。

## 三、第三步：存库——格式统一才有用

转完不能散落在各个文件夹，否则「检索」这步就废了。固定一个目录结构：

```
~/knowledge/
├── raw/            # 原始文件（网页txt、PDF、电子书），只进不出
├── md/             # 所有转好的 Markdown，按主题分子文件夹
│   ├── ai-tools/
│   ├── papers/
│   └── books/
└── INDEX.md        # 索引：每篇文章一行「标题 + 一句话总结 + 路径」
```

**重点在 `INDEX.md`**。每转完一批，让 AI 帮你生成索引行：

> "这是我这批转好的 15 篇文章的标题和第一段，请为每篇写一行：`- [标题](相对路径)：一句话说明这篇讲什么`，方便我以后快速检索。"

这个索引文件就是你知识库的「目录」，搜东西先搜它，比全文搜快得多。

## 四、第四步：检索与使用——这才是知识库的价值

建库不是为了存，是为了用。三种检索方式，按场景选：

**1. 关键词全文搜**（最快，日常用）

```bash
grep -ri "关键词" ~/knowledge/md/ | head -20
```

不区分大小写，搜到的是具体哪一行，比搜标题精准。

**2. 让 AI 帮你读**（适合跨文章找答案）

把某几个 `.md` 文件一起丢给 ChatGPT，直接提问：

> "这是我收藏的 5 篇关于 XX 的文章（见附件），请综合它们回答我：1. 它们的共同结论是什么？2. 观点有冲突的地方在哪？"

这是知识库最值钱的用法——**单篇文章你读得懂，但「跨文章的综合判断」才是 AI 真正帮你省时间的地方**。

**3. 大库升级**（文章到几百篇以后）

全文搜开始变慢、AI 一次塞不下那么多文件时，就该上向量检索了。推荐去 [duckdblab.org/zh/](https://duckdblab.org/zh/) 看看它的本地数据库方案，把每篇文章的摘要存成结构化数据，用自然语言直接查，比 `grep` 智能得多，且数据全程留在本地不上云。

2. **[正则表达式构建器](https://198007.xyz/tools/regex-builder/)**：想统一清理正文里残留的「广告位」「推荐阅读」这类固定模式，用它可视化写出正则再批量替换，比手写稳。

## 六、避坑清单（90% 的人栽在这几处）

| 坑 | 现象 | 解法 |
|----|------|------|
| PDF 双栏文字交错 | 读起来左右跳 | 明确告诉 AI「按阅读顺序合并，不要按版面」 |
| 一次塞太多 | 输出被截断、后半篇丢了 | 拆章节分批，每批不超过 50 页 |
| 图片丢成空链接 | 公式/图全没了 | 转完用 Markdown 预览工具扫一遍，标注哪些图需要手动补 |
| 来源没记 | 以后引用不知道出处 | 提示词里固定加「来源：URL」，养成习惯 |
| 库建完再没用过 | 知识吃灰 | 每转一批就在 INDEX.md 里强制写一句话总结 |
