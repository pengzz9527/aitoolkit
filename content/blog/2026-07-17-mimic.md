## 工具简介

**Mimic** 是一款由 littledivy 开发的开源 AI 驱动工具，目前已在 GitHub 上斩获 **1,113 ⭐**（144 Forks），迅速登上 Trending 榜单。它的核心理念非常简洁：**拦截任意 App 的网络流量，然后用 AI 自动生成对应的 Python 客户端库，让你能像调用 Python 函数一样使用任何 App 的接口。** 在逆向分析过程中，如果需要将捕获的 HAR 文件或 cURL 请求转换为易读的格式，本站的 [JSON 格式化工具](/tools/json-formatter/) 会派上用场。

一句话总结：**Mimic 是一个零代码逆向工具——你只需正常使用 App，它就能自动捕获流量、提取认证信息，并生成可直接调用的 Python 客户端。**

与传统的 API 逆向方案不同，Mimic 不需要你手动分析数据包、伪造请求或编写复杂的 HTTP 客户端。它的工作流程是：用 mitmproxy 捕获 App 流量 → 用 Claude 等 AI 模型分析流量结构 → 自动生成 Python 客户端代码。生成的代码是基于 `mimic.App` 的标准 Python 库，你可以直接导入使用，也可以根据需要自行修改。

## 核心功能

### 1. AI 驱动的自动代码生成

Mimic 的最大亮点在于将 AI 集成到了逆向工作流中：

- **流量捕获**：内置 mitmproxy 支持，自动拦截 App 的所有网络请求
- **AI 分析**：利用 LLM（如 Claude）分析捕获的请求模式、认证方式和数据结构
- **代码生成**：自动生成结构化的 Python 客户端代码，包含命名方法、参数模板和多步骤调用链

```python
from hinge_client import Hinge

acc = Hinge()                 # 复用捕获的会话
recs = acc.get_recommendations()
acc.like(subject_id, comment="hi lol")
```

### 2. 灵活的流量捕获方式

Mimic 支持三种流量捕获后端，适应不同场景：

| 捕获方式 | 适用场景 | 是否需要证书 |
|---------|---------|------------|
| **mitmproxy** | iOS/Android 应用 | 需要安装 CA 证书 |
| **cURL 粘贴** | 有 Web 版本的应用 | 不需要 |
| **HAR 文件** | 浏览器开发者工具导出 | 不需要 |

对于有 Web 版本的应用，可以直接在浏览器 DevTools 中"复制为 cURL"，然后 `Session.from_curl(text)` 即可；对于纯移动端应用，可以通过配置手机代理来捕获流量。

### 3. 智能认证管理

大多数 App 的请求都依赖稳定的认证信息（Bearer Token、设备 ID、Session ID、Cookies 等）。Mimic 能够：

- **自动提取认证信息**：从捕获的流量中提取所有必要的认证凭据
- **Token 自动刷新**：当检测到 401 错误时，自动从 mitmweb 重新拉取 token 并重试请求
- **会话持久化**：支持通过 `Session.from_mitm()`、`Session.from_curl()`、`Session.from_har()` 多种方式构建会话

### 4. 证书钉扎绕过

部分应用（如银行类 App、Instagram）使用了证书钉扎（Certificate Pinning）技术来防止中间人攻击。Mimic 提供了 Frida-based 的绕过方案：

```bash
mimic unpin <ipa|bundle-id>
```

这条命令会自动配置 Frida 脚本，解除证书钉扎限制，让 mitmproxy 能够正常捕获流量。

### 5. 轻量级零依赖设计

Mimic 本身是一个 Python 包，mitmproxy 通过 `uvx` 按需启动，无需单独安装。安装过程极其简单：

```bash
sh install.sh          # 自动安装 uv 和 mimic
mimic doctor           # 确认代理 + Claude 就绪
```

## 与同类工具对比

| 特性 | Mimic | Apify | Postman + 手动 | curl + 脚本 |
|------|-------|-------|---------------|-------------|
| 自动化程度 | **全自动**（AI 生成代码） | 高（需配置爬虫） | 低（手动分析） | 极低（手写代码） |
| 上手难度 | 低（一条命令开始） | 中等 | 高 | 高 |
| 移动端支持 | ✅ mitmproxy 捕获 | ❌ 主要 Web | ❌ 主要 Web | ❌ 主要 Web |
| 认证处理 | 自动提取 + 刷新 | 需手动配置 | 手动复制 | 手动复制 |
| 证书钉扎 | 内置 Frida 绕过 | 不支持 | 不支持 | 不支持 |
| 输出格式 | Python 客户端库 | JSON/CSV | 手动导出 | 原始数据 |
| 价格 | 免费开源 | 按量付费 | 免费/付费 | 免费 |
| GitHub Stars | ~1,100 | N/A | N/A | N/A |

**与 Apify 相比**：Apify 提供的是预构建的爬虫平台，适合大规模数据采集但成本高且不够灵活。Mimic 更轻量、更定制，生成的代码完全由你控制。

**与 Postman 手动分析相比**：Postman 需要大量手工操作来分析请求结构和构造请求，而 Mimic 通过 AI 自动化了这一过程，效率提升显著。

**与 curl 脚本相比**：curl 方案需要手动编写每个请求的逻辑，包括认证、重试、错误处理等，Mimic 生成的代码已经包含了这些逻辑。

## 如何使用

### 安装步骤

1. **运行安装脚本**：

   ```bash
   curl -fsSL https://raw.githubusercontent.com/littledivy/mimic/main/install.sh | sh
   ```

   该脚本会自动安装 `uv`（如果未安装），然后在隔离环境中安装 Mimic。

2. **检查环境**：

   ```bash
   mimic doctor
   ```

   确认代理和 AI 模型都已就绪。

### 基本操作流程（以 iOS 应用为例）

1. **启动捕获**：

   ```bash
   mimic record
   ```

   命令会显示你的 Mac 局域网 IP，并引导你在 iPhone 上配置代理。

2. **配置 iPhone 代理**：
   - 打开 iPhone「设置」→ Wi-Fi → 点击当前网络旁边的「i」
   - 配置代理 → 手动 → 输入 `<your-mac-ip>:8080`
   - 在 Safari 中访问 `http://mitm.it` → 安装 Apple 配置文件
   - 「设置」→「通用」→「关于本机」→ 证书信任设置 → 开启 mitmproxy 完全信任

3. **正常使用 App**：
   - 在 iPhone 上打开目标 App，进行你需要的操作
   - Mimic 会自动捕获所有网络流量

4. **生成客户端**：

   ```bash
   mimic hosts                    # 列出捕获的主机
   mimic learn prod-api.hingeaws.net  # 查看捕获的端点
   mimic gen prod-api.hingeaws.net    # 生成客户端代码
   ```

5. **使用生成的客户端**：

   ```python
   from hinge_client import Hinge

   acc = Hinge()
   recs = acc.get_recommendations()
   print(recs)
   ```

### 不使用代理的方式（Web 应用）

如果目标应用有 Web 版本，可以跳过代理配置：

```python
from mimic import Session

# 方式一：从浏览器 DevTools 复制的 cURL
with open("copied.txt") as f:
    session = Session.from_curl(f.read())

# 方式二：从 HAR 文件加载
session = Session.from_har("traffic.har", "api.example.com")

# 方式三：显式指定
session = Session(base_url="https://example.com", headers={...})
```

## 局限性

了解 Mimic 的局限性同样重要：

- **证书钉扎应用**：虽然 Mimic 提供了 Frida 绕过方案，但某些银行类 App 的反调试保护可能使绕过变得困难
- **DPoP 令牌**：使用动态绑定证明（DPoP）的应用，每个请求都需要新的私钥签名，Mimic 的核心模型在此场景下不适用
- **仅限自己的账户**：Mimic 回放的是你自己的会话，不能用于访问他人的账户
- **需要 AI 模型**：代码生成阶段依赖 Claude 等 LLM，需要配置 API key

## 总结

### 优点

- ✅ **真正的零代码体验**：从流量捕获到客户端生成，全程几乎无需手动编码
- ✅ **AI 驱动的智能分析**：自动识别 API 模式、认证方式和数据结构
- ✅ **多种捕获方式**：支持 mitmproxy、cURL、HAR 三种后端，适应各种场景
- ✅ **智能认证管理**：自动处理 token 刷新和重试逻辑
- ✅ **MIT 许可证**：商业和个人均可自由使用
- ✅ **极致轻量**：零额外依赖，一条命令即可开始

### 不足

- ⚠️ 对 DPoP 等高级认证方案不支持
- ⚠️ 需要配置 AI 模型 API key 才能完成代码生成
- ⚠️ 证书钉扎应用需要额外的 Frida 配置
- ⚠️ 社区规模较小，文档和社区资源有限
