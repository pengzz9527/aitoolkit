# Aider 评测：终端里的 AI 结对编程神器

很多人写代码离不开 IDE 里的 AI 补全，但真正需要让 AI 理解整个项目结构、跨文件修改、并自动提交 Git 时，补全工具就不够用了。**Aider** 正是为此而生——它运行在你的终端里，通过 LLM 直接读取、修改并 `git commit` 你项目里的代码，相当于一个能自主操作 Git 仓库的 AI 结对程序员。项目自 2023 年开源，星标数已突破 **4.95 万**，是终端 AI 编程工具里最成熟、最活跃的之一。

## 工具简介

**Aider** 是一款 AI 驱动的结对编程 CLI 工具，核心理念是让 LLM 直接在你的 Git 仓库中工作，而不是在 IDE 里做文本补全：

- **GitHub**: https://github.com/Aider-AI/aider
- **官网**: https://aider.chat
- **语言**: Python
- **开源协议**: Apache-2.0
- **支持模型**: OpenAI、Anthropic Claude、Google Gemini、本地 Ollama 等

## 核心功能

1. **仓库感知（Repo Map）**：自动用 tree-sitter 生成代码结构地图，让 LLM 理解整个项目的类、函数、调用关系，而不只是当前文件。
2. **多文件编辑**：一次对话可以同时修改多个文件，AI 按语义定位而非单纯靠文本匹配，跨文件重构更可靠。
3. **自动 Git 提交**：每轮修改后 Aider 自动生成规范的 commit message 并提交，出问题可一键 `git revert` 回滚，安全性极高。
4. **模型无关**：通过 OpenRouter 或直接接入 OpenAI/Anthropic/Ollama，想用最强的还是想用本地的都能配置。
5. **聊天式协作**：终端里像聊天一样下指令，支持 `ask` 模式（只解释不改代码）、`architect` 模式（先出方案再实现）等多种工作流。

## 适用人群

- 习惯终端工作、不想离开 shell 的开发者
- 需要跨多文件重构、且希望 AI 改动可追溯可回滚的团队
- 想在本地/私有环境跑 LLM（Ollama）做代码协助、注重数据隐私的人
- 想快速把一段自然语言需求变成可运行代码的个人开发者

## 与同类工具对比

| 工具 | 形态 | 优势 | 局限 |
| --- | --- | --- | --- |
| **Aider** | 终端 CLI | Git 原生、自动提交、仓库感知、模型灵活 | 无图形界面，纯文本协作 |
| **Claude Code / Codex CLI** | 终端 CLI | 深度代理、可执行命令 | 偏执行型代理，轻量结对场景稍重 |
| **Cursor / Copilot** | IDE 内嵌 | 图形化、补全即时代码 | 强绑 IDE，跨文件自主提交能力弱 |

一句话：**要 IDE 里实时补全选 Cursor/Copilot；要深度自动化代理选 Claude Code；要在终端里轻量、可追溯地结对编程，Aider 是首选。**

## 如何使用（具体步骤）

**1. 安装**（推荐用 pip 或 uv）：

```bash
pip install aider-chat
# 或
uv tool install aider-chat
```

**2. 配置 API 密钥**（以 OpenAI 为例，其他模型同理）：

```bash
export OPENAI_API_KEY=sk-xxx
```

**3. 进入你的 Git 仓库并启动 Aider**：

```bash
cd my-project
aider --model claude-sonnet-4-5
```

**4. 把要处理的文件加入上下文**（Aider 才知道改哪些文件）：

```bash
/add src/main.py
/add src/utils.py
```

**5. 用自然语言下指令**，例如：

```
给 main.py 加一个带重试的 HTTP 请求函数，并把逻辑抽到 utils.py
```

**6. 查看改动并自动提交**：Aider 每轮会展示 diff 并生成 commit，不满意随时 `git revert`。

**小贴士**：用 `/ask` 只解释不改代码，用 `architect` 模式可让先出实现方案再动手，大改动更稳妥。

## 总结与推荐指数

Aider 把「AI 写代码」这件事从 IDE 里的补全，升级成了**终端里可追溯、可回滚的结对编程**，Git 原生 + 仓库感知是它最独特的卖点。上手成本低、模型灵活、对本地 LLM 友好，非常适合习惯命令行、重视代码可追溯性的开发者。

- 适合：终端重度用户、需要跨文件可追溯改动的团队
- 不适合：完全零命令行基础、只想要图形化补全的新手
