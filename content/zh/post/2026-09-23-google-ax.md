# Google AX：用 Kubernetes 的方式编排 AI Agent，声明式任务调度新范式

在 AI Agent 快速爆发的 2026 年，如何高效、安全地批量运行和管理成百上千个 Agent 任务，成了企业和开发者面临的新挑战。**Google 开源的 AX**（axolotl）正是为这个问题而生的 —— 它是一个声明式的 Agentic 编排运行时，让你用类似 Kubernetes 的 YAML 配置文件来定义 Agent 任务、工作空间和网关策略，然后由 AX 负责沙箱隔离、资源调度和运行管理。

目前 AX 在 GitHub 上已获得 **7,940+ 星标**，由 Google 官方维护，采用 Apache-2.0 许可证，底层依赖 [Agent Substrate](https://github.com/agent-substrate/substrate) 提供沙箱执行能力。

- **GitHub 星标**：7,940+
- **GitHub 仓库**：https://github.com/google/ax
- **许可证**：Apache-2.0
- **语言**：Go
- **定位**：Agentic 编排运行时

## 一句话简介

> **AX** 是一个高吞吐量的声明式 Agent 编排平台，你只需编写 YAML 描述任务目标、工作空间和网络策略，AX 负责在 Kubernetes 集群中沙箱化执行、调度并监控这些 Agent 工作负载，理念上与 Kubernetes 编排容器的方式一脉相承。

## 核心功能

### 1. 声明式任务定义（YAML Manifests）

AX 的核心设计哲学是"一切皆 Manifest"。你可以用标准的 `ax.io/v1alpha1` YAML 文件来定义：

```yaml
# task.yaml
apiVersion: ax.io/v1alpha1
kind: Workspace
metadata:
  name: golang
spec:
  git:
    - repo: https://github.com/golang/go.git
      branch: "my-fix"
---
apiVersion: ax.io/v1alpha1
kind: Task
metadata:
  name: test
spec:
  workspaces:
    - name: golang
      goal: "Ensure that Go tool chain is available and is built from source"
  debug: true   # lets you `ax ssh` into the sandbox
```

这种声明式方式让你可以像管理 K8s Pod 一样管理 Agent 任务，版本控制、CI/CD 集成、审计追踪都变得自然。

### 2. 四种核心原语

AX 提供了四个小而精的原语来覆盖 Agent 运行的关键需求：

| 原语 | 作用 | 对应 K8s 概念 |
|------|------|-------------|
| **Task** | 定义一个 Agent 任务及其目标，运行在沙箱中 | Pod |
| **Workspace** | 预置 Git 仓库、MCP 服务器和 Skill 包，让 Agent 启动时即"热启动" | ConfigMap + Volume |
| **Gateway** | 锁定出站流量到显式允许的主机白名单 | NetworkPolicy |
| **Model** | 配置平台使用的 LLM 及凭据（从 K8s Secret 读取） | Secret |

这种简洁的设计避免了过度抽象，每个原语都有明确的边界和职责。

### 3. 沙箱隔离与网络围栏

每个 Task 都在隔离的沙箱中运行，具备 CPU/内存限制。Agent Substrate 提供了底层的沙箱执行环境，AX 在其上增加了网络围栏能力 —— 通过 Gateway 资源，你可以精确控制每个 Agent 能访问哪些外部服务，防止 Agent 在循环中无限调用 API 或访问未授权资源。

这对于运行不可信的 Agent 代码至关重要，尤其是当 Agent 可以执行任意 shell 命令时。

### 4. 暂停与恢复（Suspend / Resume）

Agent 既不是无状态微服务，也不是传统的批处理作业 —— 它们会累积状态。AX 支持 `ax suspend` 和 `ax resume` 命令，让你能够暂停空闲的 Agent 并在稍后精确地从中断处继续运行，避免重复计算和上下文丢失。

### 5. 实时调试与 Shell 接入

通过 `ax ssh` 命令，你可以直接 SSH 进入运行中的 Agent 沙箱，实时查看它的操作过程。配合 `ax watch` 命令，可以流式观察任务的执行日志，方便调试和排查问题。

### 6. 大规模集群调度

AX 专为"数以亿计的 Agent 任务"设计，在 Kubernetes 集群上横向扩展。如果你需要同时运行成千上万个独立的 Agent 任务（比如批量代码审查、大规模数据标注等），AX 提供了必要的调度和资源管理能力。

## 如何使用

### 环境要求

- Kubernetes 集群（1.28+）
- Go 1.22+（用于安装 CLI）
- `ko` 工具（用于构建和部署镜像，`brew install ko`）
- 一个容器镜像仓库（集群可以拉取）
- Agent Substrate Control API（默认集群内地址：`api.ate-system.svc.cluster.local:443`）

### 安装 CLI

```bash
go install github.com/google/ax/cmd/ax@latest
```

安装后确保 `$(go env GOPATH)/bin` 在 PATH 中。

### 部署控制平面

```bash
make deploy AX_IMAGE_REPO=<your-registry>
```

这个命令会部署 Redis，然后用 `ko` 构建并部署控制平面镜像，所有资源落在 `ax-system` 命名空间中。

### 创建并运行第一个任务

```bash
# 1. 编写任务 YAML（见上方示例）
ax apply -f task.yaml

# 2. 实时观看任务执行
ax watch task test

# 3. SSH 进入沙箱查看 Agent 操作
ax ssh test -- ls -al /workspace
```

### 暂停与恢复

```bash
# 暂停空闲任务
ax suspend task test

# 恢复任务
ax resume task test
```

## 总结

AX 代表了 AI Agent 基础设施的一个重要方向：**从脚本化的 Agent 运行走向声明式、可编排、可规模化的 Agent 平台**。Google 将 Kubernetes 的成功经验迁移到了 Agent 领域，用四种核心原语（Task、Workspace、Gateway、Model）覆盖了隔离、预置、安全和配置这四大关键需求。

当然，AX 仍处于积极开发阶段，官方明确警告核心概念、协议和规范可能在大版本发布前引入重大破坏性变更。对于早期采用者来说，这意味着需要持续关注更新并准备好调整配置。

如果你正在搭建企业级 Agent 平台，或者对 Agent 编排的基础设施感兴趣，AX 值得深入关注和试用。它可能成为未来 AI Agent 基础设施的事实标准之一。
