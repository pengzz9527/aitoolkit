# Magpie 评测：一个网关管所有 AI 智能体的模型与账号

用 AI 写代码的人越来越多，但麻烦也同步膨胀：Claude Code 用 Anthropic 订阅、Codex 用 OpenAI 账号、Gemini CLI 用 Google 额度，每家配置格式不同、密钥不同、额度不同，一家的用完了另一家的还没用上。**Magpie** 就是来解决这个问题的——它在你本机跑一个网关，把所有智能体统一接入，想用 DeepSeek 驱动 Claude Code、用 Kimi 跑 Codex 都行，额度耗尽自动切换到下一个账号，全程不需要你手动改配置。项目 2026 年 9 月开源，三个月内星标数已突破 **1.4 万**，增长极快。

## 工具简介

**Magpie** 是一款本地 AI 模型网关 + 管理工具，核心理念是「所有智能体的模型，一个地方管」：

- **GitHub**: https://github.com/yetone/magpie
- **官网**: https://usemagpie.ai
- **语言**: Go
- **开源协议**: MIT
- **支持平台**: macOS（菜单栏应用）、Windows、Linux、Docker、Termux，另提供 TUI 与 Web UI
- **支持智能体**: Claude Code、Codex、Gemini CLI、Cursor、Cline、Zed、VS Code、Copilot 等 50+ 款

## 核心功能

1. **任意模型配给任意智能体**：在统一的模型选择器里为每个智能体选模型（`provider/model` 格式），Magpie 自动改写该智能体自己的配置文件，且保留原有注释与格式，不破坏现有设置。
2. **本地网关协议转换**：网关监听 `127.0.0.1:3425`，同时支持 OpenAI Chat/Responses、Anthropic Messages、Gemini 四种协议并互相转换，工具调用、流式输出、推理内容均可透传。
3. **路由组与故障转移**：把多个模型/账号编成一个路由组，支持五种策略——`smart`（优先快用完额度的账号，减少浪费）、`order`（顺序兜底）、`rotate`（轮流）、`usage`（用量最少的优先）、`pace`（按重置节奏分配）。某个账号额度耗尽时自动切到下一个，智能体端无感知。
4. **订阅账号统一管理**：不仅管 API Key，还能识别你已登录的 Claude、ChatGPT、Copilot、Gemini 等订阅，把它们的模型提供给其他智能体使用；支持「每日预热」功能，定时消耗各账号 5 小时窗口额度，避免浪费。
5. **用量与成本看板**：实时统计每个账号的 token 消耗、缓存命中率、花费（美元/人民币），支持按账号和上游密钥出账单，可导出 OTLP 到自有监控系统；还有会话列表，可一键在终端中重开任意历史对话。

## 适用人群

- 同时使用多个 AI 智能体（Claude Code + Codex + Gemini CLI…）的开发者
- 持有多个 AI 订阅（Claude Pro、ChatGPT Plus、Copilot 等）但额度经常浪费的用户
- 想低成本使用各家模型（如用 DeepSeek 驱动 Claude Code）的进阶用户
- 小团队需要集中管理 AI 用量、控制成本的技术负责人

**不适合**：只用单一智能体 + 单一订阅、且配置简单不需要切换的人——对这类用户，Magpie 是多余的一层。

## 如何使用（具体步骤）

**1. 安装**（任选其一）：

```bash
# 官网一键脚本（macOS/Windows/Linux）
curl -fsSL https://usemagpie.ai/install.sh | sh

# 或 Go 安装
go install github.com/yetone/magpie@latest

# 或 Docker
docker run -d -p 3425:3425 ghcr.io/yetone/magpie
```

macOS 版为菜单栏应用，安装后常驻右上角；Linux/Windows 有窗口版与 TUI。

**2. 添加供应商**（Providers → Add provider）：

- API Key 供应商：粘贴密钥即可，如 `magpie provider add deepseek sk-…`
- 订阅账号：登录 Claude / ChatGPT 等，Magpie 自动识别已登录的订阅
- 本地模型：填 Ollama / LM Studio 地址即可

**3. 为智能体指定模型**（Agents 页面）：

```bash
# Claude Code 用 DeepSeek 驱动
magpie claude deepseek/deepseek-v4-pro

# Codex 用 Kimi 驱动
magpie codex moonshot/kimi-k2.5

# Gemini CLI 用 GLM 驱动
magpie gemini zhipu/glm-5.3
```

下次启动对应智能体的新会话即生效，无需手动改配置。

**4. 创建路由组（可选，多账号容灾）**：

```bash
magpie group add "Opus anywhere" \
  models=claude/claude-opus-5-5,copilot/claude-opus-5.5 \
  routing=smart
magpie claude group/opus-anywhere
```

`smart` 模式会自动优先使用快用完额度的账号，减少浪费。

**5. 查看配额与花费**：

```bash
magpie quota   # 各账号剩余额度
magpie tui     # 终端全功能界面
```

**6. 保存配置方案（Profiles）**：

```bash
magpie save work      # 保存当前所有智能体配置
magpie use work       # 一键切换回工作模式
```

**小贴士**：若不希望 Magpie 自动识别订阅账号（隐私考虑），可在 Settings → Privacy 关闭「Subscription accounts」，或运行 `magpie accounts discovery off`；API Key 供应商不受影响。

## 总结与推荐指数

Magpie 解决了多智能体时代最现实的痛点：**配置碎片化与订阅额度浪费**。它用本地网关把 50 多款智能体统一接进一个应用，五种路由策略让额度利用最大化，配额面板让花销透明可查。对重度 AI 开发者而言，这套工具链几乎是刚需；对只用单一订阅的轻度用户则有些过剩。

- 适合：多智能体重度用户、多订阅持有者、注重 AI 成本控制者
- 不适合：单一智能体单一订阅、不打算折腾配置的用户

**推荐指数：⭐⭐⭐⭐（4.0 / 5）**
