## 一句话介绍

**human-writing（活人感写作）** 是一款开源的通用中文创作与改稿 Skill，专为 Claude Code、Codex、Cursor 等 AI 编程助手设计。它的核心目标是解决 AI 写中文的通病——读起来流畅但说不出是谁写的，让模型输出更像"一个具体的人在说话"。

## 它是什么？

AI 写作中文有个普遍问题：文字流畅、结构完整，但读完后你感觉不到背后有一个具体的人。这种"模型腔"表现为：冒号滥用、"不是……而是……"类翻案句频繁出现、三段式排比、以及"赋能""抓手""闭环"等商业黑话的泛滥。

**human-writing** 正是为了解决这个问题而生。它不是简单的关键词替换工具，而是一套完整的写作方法论——从材料核验、事实核查到修辞检查，层层过滤掉"AI 味"。项目由开发者 KKKKhazix 于 2026 年 8 月 5 日开源，上线不到两周已收获 **2700+ Stars**，采用 **MIT 许可证**，主语言为 **Python**，最新版本为 **v1.1.0**。

## 核心功能

### 1. 材料优先的写作流程

human-writing 的第一个核心原则是：**先有材料，再动笔**。对于现实题材，它要求作者先清点用户提供的经历、数字、原话，或主动查询公开资料。如果凑不够至少五件具体材料，就不应该写长文——宁可缩短篇幅，也不用车轱辘话凑字数。

这一设计直击当前 AI 写作的一大弊病：为了迎合字数要求，模型往往会重复解释、堆砌同义改写，或者凭空编造"比如有个人"类的典型场景。human-writing 从源头上堵住了这条路径。

### 2. 修辞级的翻案腔禁令

v1.0 版本采用字符串级禁令（禁用"不是……而是……"等具体句式），但很快发现模型会换一套字面继续做同样的事——"你以为……其实……""回头才发现""与其说A不如说B"本质上是同一套动作。

v1.1 将防线从字面升级到**修辞动作级**：禁令针对的是"先给读者立一个他没有的误解，再推翻它抬价"这一行为本身，不管它穿什么外衣。检测脚本同步升级，新增了翻案腔变形族检测、三连以上同构排比检查、名词化句式警告，以及句长变异系数和连词密度的统计层检查。

### 3. 多场景适配

human-writing 针对不同文体准备了精细的参考文件：

- **`references/forum-prose.md`**：知乎回答、公众号文章、论坛长帖的写法，侧重节奏和措辞
- **`references/reality.md`**：真人、历史、新闻、数据、个人经历的事实边界
- **`references/fiction.md`**：小说、故事、虚构散文和对白的创作规则
- **`references/formats.md`**：短内容、口播、演讲、教程、评测等特殊形式
- **`references/revision.md`**：初稿完成后的逐段检查规则

### 4. 蒸馏版开箱即用

针对无法加载 Skill 的场景（如 ChatGPT、千问办公、WorkBuddy 等聊天窗口），项目提供了 **2000 字以内的蒸馏版**（`dist/human-writing-lite.md`）。只需将这段内容粘贴给模型，即可在五条评价规则的约束下产出更自然的中文。

### 5. 自动化检测脚本

项目附带了 `scripts/check_prose.py`，可在初稿完成后自动检查：

- 翻案腔变形句（跨句「。而是」、换字「倒不如/毋宁」等）
- 模型偏爱抒情词（安放、抵达、微光、褶皱等）
- 「」高亮短语过密
- 句长变异系数过低（句子节奏太平）
- 连词密度过高

## 适用人群

- **中文内容创作者**：知乎答主、公众号写手、博客作者，希望减少 AI 辅助写作时的"模型腔"
- **AI 编程助手用户**：使用 Claude Code、Codex、Cursor、OpenCode 等工具的用户，可直接安装 Skill 获得即开即用的写作能力
- **需要批量改稿的团队**：通过自动化检测脚本，对已有文本进行批量"去 AI 化"检查
- **中文写作教学场景**：其方法论本身可作为理解"好中文"与"AI 中文"差异的参照系

与市面上常见的"AI 写作去重工具"不同，human-writing 不依赖关键词替换，而是从写作流程层面介入——从材料准备到初稿完成再到逐段检查，形成完整闭环。这也是它能在 GitHub 上迅速获得认可的原因。

## 如何使用

### 方式一：Agent Skill 安装（推荐）

如果你使用 Claude Code、Codex、Cursor 等支持 Skill 的 AI 编程助手，只需将以下指令发给你的 Agent：

```
帮我安装这个 skill：https://github.com/KKKKhazix/human-writing
```

Agent 会自动读取仓库并完成安装。装好后可直接使用：

```
使用 human-writing，把我的材料写成一篇有活人感和中文韵律的作品。
```

### 方式二：手动安装

如果 Agent 不支持直接安装，可从 [Releases 页面](https://github.com/KKKKhazix/human-writing/releases/latest) 下载，或将仓库中的 `human-writing` 文件夹复制到本地 Skills 目录：

```
~/.agents/skills/human-writing/
```

### 方式三：蒸馏版直接使用

对于不支持 Skill 的场景，将 `dist/human-writing-lite.md` 的内容直接粘贴给 ChatGPT、千问办公、WorkBuddy 等聊天产品即可。

### 方式四：本地检测脚本

安装完成后，可运行检测脚本对已有文本进行检查：

```bash
python scripts/check_prose.py your_article.md
```

## 总结

human-writing 的巧妙之处在于，它没有停留在"禁用某些词"的表层，而是深入到了**写作行为本身**——从材料准备到修辞选择，建立了一套可执行、可检测、可迭代的方法论。v1.1 将禁令从字符串升级到动作级，体现了作者对 AI 行为模式的深刻理解。

对于经常使用 AI 辅助中文写作的用户来说，human-writing 是目前GitHub 上最实用的中文写作 Skill 之一。2700+ Stars 和快速迭代（1.0 到 1.1 仅隔数日）印证了它的实际需求。
