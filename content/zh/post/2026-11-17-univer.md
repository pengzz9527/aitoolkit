# Univer 评测：飞书团队开源的「AI Agent 办公底座」，表格/文档/幻灯片一个 SDK 搞定，Agent 和人编辑同一个文件

**Univer** 出自飞书文档背后的团队 **DreamNum**（同团队还维护着开源表格组件 x-spreadsheet），是一个开源 Office SDK：把电子表格、文档、幻灯片、多维表格（Base）、画板（Board）、PDF 放进同一套运行时里，你可以用它在自己产品内嵌一个完整的办公编辑面。它的仓库描述已经从「办公组件」升级为 **The Office Harness for AI Agents**——给 AI Agent 提供一套「能读、能写、能验证」的 Office 基础设施，Agent 和人在同一份文件里协作。

它 2022 年 9 月创建，GitHub 星标 **27,500+**（Fork 2,500+），已发 **123 个 release**，最近一周重新登上 GitHub Trending 总榜（Trending 当日榜第 3），是当前「Agent 办公化」这条线上最完整的开源底座。

- **GitHub 星标**：27,500+（周增 +1,000 星，Trending 总榜在榜）
- **GitHub 仓库**：https://github.com/dream-num/univer
- **官网**：https://univer.ai
- **文档站**：https://docs.univer.ai
- **许可证**：Apache-2.0（开源核心）；Pro 插件、Server SDK、部分 AI SDK 扩展为商业授权，独立分发
- **语言**：TypeScript
- **创建时间**：2022-09-29，最新 v1.5.0
- **生态**：Univer Workspace（自托管参考应用）、Univer CLI（Agent 本地 Office CLI）、Univer MCP、univer-sdk-skills（Agent Skills）、Univer Office Copilot

## 核心功能

### 1. 一个 SDK 覆盖整条办公线，Canvas 渲染扛得住大文件

Univer 不是「一个 Excel 组件」，而是 **Sheets / Docs / Slides / Base（多维表格）/ Board（画板）/ PDF 六个内容类型共享同一套运行时**：Canvas 渲染引擎 + 独立公式引擎 + 命令系统。内容可以在不同 Office 类型之间组合引用——仪表盘页面上的指标、图表、控件直接绑定到表格单元格，数据联动更新，这是独立拼 x-spreadsheet + 文档编辑器做不到的。

v1.5.0（最新）的重点更新：图表独立工作表（chart sheet）、堆叠折线图、各系列误差线、Board 可编辑图表布局 + LaTeX 渲染包、公式计算内存占用显著下降、Excel 兼容修复（`ISOWEEKNUM`、`WEEKNUM`、`PV`、复数类型等）。

### 2. 插件化组装 + 统一 Facade API，浏览器和 Node.js 同一套

每个能力（表格核心、公式、数值格式、图表、协作……）都是独立插件，用官方 **presets** 一行引入，也可以手动组合、替换、懒加载任何一层。对上，所有编辑面暴露统一的 **Facade API**（workbook / range / formula / command / event 一层接口），浏览器和 Node.js 里写法完全一致——应用代码不关心底层渲染，Agent 代码同理。

快速上手（Vite/任意打包器环境，纯开源包，不需要商业授权）：

```bash
pnpm add @univerjs/presets @univerjs/preset-sheets-core
```

```ts
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'
import '@univerjs/preset-sheets-core/lib/index.css'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: { [LocaleType.EN_US]: mergeLocales(UniverPresetSheetsCoreEnUS) },
  presets: [UniverSheetsCorePreset({ container: 'app' })],
})
univerAPI.createWorkbook({})
```

然后 `univerAPI` 就是你的数据通路：`sheet.getRange('A1:D4').setValues([...])` 写单元格、公式自动重算、`workbook.save()` 拿快照，React/Vue/Web Components 官方都有适配器，组件卸载时调 `univer.dispose()` 即可。

### 3. Headless 模式：没有界面的 Office 引擎，跑在 Node.js 里

这是 Univer 区别于所有「Web 表格组件」的关键点：同一套内容模型、命令系统和公式计算引擎可以在 **无渲染环境（Node.js）里跑**。你可以在服务端做批量报表生成、数据清洗、公式重算、文件转换，不需要开浏览器；CI 里跑自动化校验也是同一条路。Agent 侧的「程序化编辑 + 结果校验」正是建立在这个能力上的。

### 4. 面向 Agent 的三件套：程序化编辑 / 输出验证 / Worktree 协作

Univer 官方给出的 Agent 工作流（AI SDK 文档）明确分三步：

1. **程序化编辑**：Agent 通过 Facade API 检查、修改表格/文档内容；
2. **输出验证**：Agent 不能只说「写完了」，它要读回内容、看渲染截图、跑布局诊断（比如幻灯片文字是否溢出、是否出页）；
3. **Worktree 协作**：Agent 的改动全部落在**隔离草稿区**（worktree），人看的是 diff 视图，决定 merge / 继续改 / 丢弃——和 Git 工作流同构，误改零风险。

### 5. Agent 生态全家桶：CLI、MCP、Skills、Copilot 参考应用

- **Univer CLI**（`dream-num/univer-cli`）：给编码 Agent 的本地 Office 命令行工作区。装上官方 `univer-cli` Skill，Agent 就能创建/编辑 Sheet、Doc、Slide、Base、Board，支持导入 Excel/CSV/Word/PowerPoint、导出标准 Office 格式，改动全部在 Worktree 隔离草稿里，完成后返回本地 Viewer URL 给人审核；
- **Univer MCP**（`dream-num/univer-mcp`）：MCP 集成，用自然语言驱动 Univer Sheets；
- **univer-sdk-skills**：官方 Agent Skills 束，覆盖 SDK 集成、Pro 功能、插件开发、Node 后端；
- **Univer Office Copilot**：LangChain + 自带模型（BYO model）的完整参考应用，内置财务模型、研报、幻灯片、运营看板等六个可编辑示例，可直接 `pnpm dev` 跑起来（本地示例不需要 AI key）；
- **Univer Workspace**：开源可自托管的完整工作区应用，人和 Agent 在里面创建、协作、审核 Office 内容，可直接当参考实现读。

## 适用人群

- **做 SaaS / BI / AI 产品的团队**：在自己应用里嵌表格/文档/幻灯片编辑面，不想被 Google Docs 这类 SaaS API 锁死，也想要比「只读组件」更完整的编辑能力；
- **AI 应用开发者**：想让 Agent 不只是「生成一段 Markdown」，而是产出**可直接打开的 xlsx / docx / pptx 文件**，并且能自己验证排版质量；
- **需要自托管协作的团队**：Workspace + Server SDK 组合可以自建办公协作层，数据完全留在自己环境里；
- **飞书 / 多维表格的重度用户**：Base（多维表格）+ Board 的组合思路和飞书一脉相承，迁移概念成本低。

**不太适合：**

- **只是想找个免费在线 Office 的普通用户**：Univer 是 SDK 不是产品，直接用飞书、WPS 或 Google Workspace 更快（虽然 Workspace 可以自托管，但那是给开发者的参考实现）；
- **只需要读写 xlsx 文件**：SheetJS（浏览器/Node 解析）或 Python 的 openpyxl/pandas 一行解决，不需要引入整个 Office 运行时；
- **对商业功能有硬要求（协作、导入导出、透视表）但不想付费**：这些能力在 Univer 属于商业授权的 Pro/Server 模块，开源核心里只有编辑、公式、筛选、条件格式等基础项，选型前务必先看 https://univer.ai/compare/ 的功能矩阵。

## 与同类工具对比

| 维度 | Univer | x-spreadsheet | Handsontable | Luckysheet | Google Sheets API |
|------|--------|---------------|--------------|------------|-------------------|
| 出品方 | DreamNum（飞书团队） | DreamNum（早期项目） | Handsontable（商业） | 摩尔朗科技（维护趋缓） | Google（闭源 SaaS） |
| 形态 | **完整 Office SDK**（表格/文档/幻灯片/多维表格/画板） | Web 表格组件 | Grid 组件 | Web 表格 | SaaS REST API |
| 渲染 | Canvas + 公式引擎 | Canvas | DOM（Grid） | Canvas | — |
| AI Agent 支持 | **原生**：Facade API / Headless / CLI / MCP / Skills / Worktree | ✗ | ✗ | ✗ | 仅 API 调用，无验证层 |
| 服务端处理 | **Node.js Headless 同一引擎** | 部分 | ✗ | ✗ | 服务端 API |
| 自托管 | ✓ | ✓ | ✓ | ✓ | ✗ |
| 协作 | 商业模块 | ✗ | ✗ | 部分 | ✓ |
| 许可证 | Apache-2.0 核心 + 商业 Pro | Apache-2.0 | MIT（免费）/ 商业（企业） | MIT | SaaS 收费 |

结论：**这张表里只有 Univer 在「AI Agent 这一列」有答案**。x-spreadsheet 和 Luckysheet 解决的是「网页里放个表格」，Handsontable 是 Grid 数据编辑，Sheets API 是远程读写——都没有「Agent 改完能自己看截图验证排版、再走人工审核合入」这条完整链路。Univer 补的正是这块：把 Office 变成 Agent 的一等可操作对象。代价是功能分层清晰（开源核心 vs 商业 Pro）和 SDK 形态本身的学习成本。

> ⚠️ 三个要留意的点：
> 1. **开源 ≠ 全免费**：实时协作、编辑历史、Office 文件导入导出、图表、透视表、打印在功能矩阵里多属于商业模块，选型前先对 https://univer.ai/compare/ 打勾；
> 2. **版本一致性**：`@univerjs/*` 包必须保持同一版本线，商业包要匹配对应 release，混装容易出怪问题；
> 3. **Agent 验证依赖本地浏览器**：CLI 的截图/打印/布局诊断需要本地装 Chrome/Chromium/Edge，纯无头服务器上要自己准备。

## 如何使用

### 路径一：在自己产品里嵌一个表格编辑器（5 分钟）

```bash
# Vite + 任意前端框架
pnpm add @univerjs/presets @univerjs/preset-sheets-core
```

页面放一个容器 `<div id="app" style="height: 100vh"></div>`，然后按上文 Quick Start 代码 `createUniver(...)` 初始化。拿到 `univerAPI` 后：

```ts
const sheet = univerAPI.getActiveWorkbook().getActiveSheet()
sheet.getRange('A1:D4').setValues([
  ['项目', '数量', '单价', '金额'],
  ['席位', 2, 25, '=B2*C2'],
])
sheet.getRange('B2').setValue(4)          // 应用代码或 Agent 走同一个口子
univerAPI.getFormula().onCalculationResultApplied().then(() => {
  console.log(sheet.getRange('D4').getValue())  // 200
})
```

React/Vue 用官方适配器包一层，卸载时 `univer.dispose()`。

### 路径二：让编码 Agent 直接干 Office 活（推荐 AI 团队先试这条）

1. 环境：Node.js 24+，给 Claude Code / Codex / Gemini CLI 等支持 Agent Skills 的 Agent 装上官方 `univer-cli` Skill（含 discovery skill 自动检查安装状态）；
2. 描述目标，例如「把这份 CSV 清成预算表，加公式、条件格式和图表，导出 xlsx」；
3. Agent 导入/创建 `.univer` 文件，在**隔离 Worktree** 里编辑、读回模型、截屏验证，标记 ready 后返回本地 Viewer URL；
4. 你在 Viewer 里看 diff（内容/格式可分开看，公式可展开），选择 **merge / 继续改 / 丢弃**——全程不动主干文件。

### 路径三：Headless 批量处理（服务端）

Node.js 里直接 import 内容模型 + 命令系统 + 公式引擎，不开 UI 就能做数据写入、公式重算、快照生成。文档：https://docs.univer.ai/guides/sheets/getting-started/node

### 路径四：自托管完整工作区

```bash
git clone https://github.com/dream-num/univer-workspace
# 按其 README 部署，得到人和 Agent 共用的自托管 Office 工作区
```

想完整看一遍「Agent 生成迷你应用 + 图表/控件绑定单元格」的形态，也可以直接读 `dream-num/univer-office-copilot` 仓库（`pnpm install && pnpm dev`，Node 24+ / pnpm 10.33.4，本地示例免 key 可逛）。

## 总结

Univer 做了一件很有想象力的事：**把整个办公层（不只是表格）做成 Agent 能程序化操作、自我验证、再交给人审核的基础设施**。Canvas 渲染 + 公式引擎扛住了大文件性能，插件架构让「只要表格核心」和「全套 Office」共用一套代码，Headless 模式把同一引擎搬进了服务端，CLI / MCP / Skills 则把编码 Agent 直接接到了 Office 生产链路上。2.75 万星、123 个 release、飞书团队背书，工程成熟度在这类「办公 SDK」里是最高的。

**扣分点：**

- **功能分层是主要劝退项**：协作、导入导出、图表/透视表等核心办公能力大量在商业模块里，纯开源版是「编辑 + 公式」基本盘；
- **SDK 形态有学习成本**：presets / 插件 / Facade / 生命周期（dispose、Steady 阶段）这套概念不是一页文档能消化的；
- **Agent 验证链路依赖本地浏览器**（截图/打印/布局诊断），纯服务器部署要额外准备；
- **Pro 模块独立授权**，团队合规要单独评审。

**推荐指数：⭐⭐⭐⭐（4/5）**

- **AI 应用开发者** → **最值得优先试**，路径二（CLI + Worktree）是目前「Agent 产出可交付 Office 文件」最完整的一条链；
- **做 SaaS/BI 嵌表格的团队** → 强烈建议把 Univer 放进选型清单，和 x-spreadsheet、Handsontable 各搭一版 PoC 对比；
- **只读 xlsx 的场景** → 别用，SheetJS/openpyxl 就够了；
- **要全套协作 + 导入导出的团队** → 先评估商业授权再动手。
