### [NVIDIA Auto Ontology — 为企业 Agent 造一层「语义地基」](https://github.com/NVIDIA/auto-ontology)
NVIDIA 开源 **Auto Ontology**（Apache-2.0），HN 上获得 **259 点赞 / 60 评论**。它要解决的问题很具体：Agent 能查数据库、能检索文档，但**答得快而答案是错的，等于零价值**。这套库从企业元数据里**自动生成本体（ontology）**，跨系统对齐「营收」「活跃用户」这类指标的定义，再通过 **MCP / CLI / API** 把上下文喂给任意 Agent harness。功能分五层：Discover（从元数据生成本体、连接既有语义模型）、Ground（给指标与实体补上可信业务含义）、Validate（用认证过的定义和血缘校验生成的 SQL，每条答案附带来源）、Expose、Learn（把人工修正折回本体）。技术栈是 Next.js 16 + FastAPI + Postgres/pgvector + Vault，推理走 NVIDIA NIM（默认 Nemotron-3-Nano-30B-A3B + Nemotron-3-Embed-1B）。值得注意的是它有两条硬约束：**目前不接受外部贡献**，且默认需要 NVIDIA API Key——HN 评论区因此吵成两派，有人称其为「企业技术债的解题钥匙」，也有人吐槽 README 是写给项目经理看的，还质疑「用更不可靠的 Agent 去修不可靠的 Agent」。但方向是明确的：Agent 可靠性瓶颈正从模型能力迁移到**上下文层**。（GitHub，HN 259 点赞）

### [Mika — 在后台屏幕替你操作 App 的端侧安卓 Agent](https://github.com/wangzan101/Mika)
**Mika** 是本周 GitHub 上升最快的 AI 项目之一，**6031 ⭐**（10 月 29 日建仓，一周内冲到 6k）。它是一个跑在手机本地的 AI 助理：你说一句话，它在**隐藏的后台屏幕**上开 App、点按钮、打字、滑动，直到把事情办完，而你可以同时继续用手机。核心设计有四点：**(1) 纯视觉操作**——像人一样看屏幕找按钮，不依赖任何 App API 或逐个 App 做集成；**(2) 会沉淀技能**——把它做成过的任务变成可复用的 skill，下次更快更稳；**(3) 数据不出手机**——没有 Mika 服务器，用自己的模型 API Key，或用 ChatGPT / xAI / OpenRouter 账号登录；**(4) 内置浏览器**——可在任意网页上说需求，手指一碰页面即中断。演示覆盖「总结群聊今天聊了什么」「找 30 美元以下 4.5 星的充电器并加购、到结账前停下」「给三个岗位的招聘方打招呼」等。它的意义不只是又一个手机 Agent，而是**把 Agent 的载体从 PC 抢回了手机**——这是 AI 助理真正的高频场景。（GitHub ⭐6031，Apache-2.0）

### [pixelfx — 244 个像素特效，每一个都是一小段代码](https://github.com/patch-gg/pixelfx)
**pixelfx** 在 GitHub 上拿到 **4090 ⭐**，思路很干净：不做素材包，做**代码库**。244 个像素艺术特效（火 12 种、爆炸 12 种、水系 12 种、冰 10 种、闪电 11 种、科幻 12 种，外加 12 套整招动作），每一个都能在浏览器里实时播放、改色、镜像，直接塞进网页游戏，或导出 sprite sheet 给任意引擎用。更有意思的是它的「表演」设计：凡是涉及角色的特效都按蓄力—出手—命中定格—收招来演，12 套完整招式把特效串成攻击动作。仓库还附带一个 **Claude Code Skill**，用「起草 → 渲染 → 看 → 修」的挑剔像素画师流程生成新特效。HN 上另一路线也在同期爆发——**Craft Anything**（8183⭐，纯 Rust 净室引擎，可研究任意网站/App/游戏再让 Agent 重建），说明「AI 生成代码 + 可直接运行的美术资产」正在成为独立游戏小团队的新工作流。（GitHub ⭐4090，MIT）

### [DeepSeek 开源 dsh-superagent：一个「只在必要时说话」的常驻编码 Agent](https://github.com/deepseek-ai/dsh-superagent-prototype)
DeepSeek 把内部在用的 **dsh-superagent** 原型公开，**16,627 ⭐ / 1.8k fork**，MIT 协议，仓库只有 **1 个 commit**——一次打包放出。它是「面向单个 GitHub 仓库的主动性编码 Agent」，作为 DeepSeek Harness 的 bundle 运行：监听 GitHub（可选飞书），有人被授权提需求时，它开一个 work item、在自己的会话和目录里干活，最后回到原对话里交答案（例如一个 PR），Web 面板显示哪些事项需要人类介入。设计哲学写得很克制：**「尽可能少占用人类注意力，尽可能多交付价值」**——能替整个团队行动的 Agent 也可能浪费整个团队的注意力，所以它**只在被要求或团队写下的规则允许时行动，只在有人必须介入或能用上结果时才开口**。仓库 README 罕见地坦白：**大部分工程由编码 Agent 自己完成**，代码属于研究性质，不是官方产品，可能有 bug、风格不一致，用前请自行审查。这既是一个 Agent 架构样本，也是一份「Agent 写 Agent」的实证材料。（GitHub ⭐16.6k，MIT）

### [《Agentic Backdoors via Pretraining Poisoning》：0.1% 投毒就能在 Agent 里埋下 RCE 后门](https://arxiv.org/abs/2610.37741)
一篇由 Xinyan Hu、Nicholas Carlini、Matthew Jagielski、Javier Rando 等 8 位作者完成的 arXiv 论文（10 月 27 日提交，cs.CR），HN 讨论 **108 点赞**。**首次证明预训练数据投毒可以在 Agent 中植入远程代码执行后门**，让它在用户机器上执行攻击者指定的命令。实验做得相当扎实：作者**从零预训练** Qwen3 的 0.6B / 1.7B / 4B 三个尺寸，再用干净的流水线 post-train 成 CLI Agent；只用新设计的 poison **污染 0.1% 的预训练语料**即可植入后门，触发词出现时执行恶意命令、干净输入上表现如常。**攻击成功率随模型规模上升**：4B 模型在 0.1% 投毒率下 ASR 约 **92%**，即使把投毒率降到 **0.0005%** 仍为正。这意味着后门不是「后训练对齐」能消掉的东西——它在权重出生之前就进去了。对正在大规模采用第三方开源权重的企业来说，这份论文给出的结论很冷：**来源不可验证的权重，等于不可验证的供应链**。（arXiv 2610.37741）

### [Sparks of Weight-Space Programming：LLM 正在学会直接读写神经网络权重](https://rikiyat.github.io/blog/weight-space-programming/)
MIT CSAIL 的 Rikiya Takehi、Jayden Teoh、Alex Zhang、Omar Khattab 于 11 月 2 日发布（作者自称「paper-shaped 的博客」），在 HN 上炸出 **2919 点赞 / 878 评论**，是今日全场最高热度。核心结论三连：**只看原始权重浮点数**，GPT-6 Astra 能判断一个网络是训练来玩哪个游戏；在没有环境反馈的情况下，它**从零写出**小的游戏策略网络，打赢用 PPO 训了 1 亿步的网络；让它在不做梯度训练的前提下提升 Qwen3.5-0.8B 的数学能力，它定位到权重里导致推理循环的问题，**原生编辑 0.016% 的权重**，MATH-500 从 7.9% 提到 **48.1%**，IFEval 顺带涨了 3 倍。作者造了个词：**Weight-Space Programming**——「我们的权重将很快由真正对权重进行推理的 LLM 来原生优化」。
争议同样激烈：spaCy 作者 Matthew Honnibal 撰文《这篇帖子具有误导性》拿到 **854 点赞**，指出原文把「不借助工具裸读裸写权重」和「允许模型写代码去改权重」两件事混为一谈，而后者只是重复了人类 ML 研究者会做的步骤；Sean Goedecke 也拆解了 Qwen 那例子。Simon Willison 随后发帖《Qwen 3.8 27B 在我笔记本上也能读懂权重》，实测本地 17GB 模型就能复现「猜游戏」任务——**这恰恰印证了争点：演示很震撼，但边界需要说清**。HN 评论区最有价值的一条观察是：所谓「递归自我改进」可能不是 Agent 改训练流程，而是模型直接改自己的权重。（MIT CSAIL，HN 2919 点赞）
