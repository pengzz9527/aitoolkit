### [AWS 官方开源 AWS Emulator：不花钱、不联网就能跑全套 AWS API](https://github.com/aws/aws-emulator)
AWS 自己下场做了 LocalStack 的活。**AWS Emulator** 是一个**本地 AWS API 模拟器**，请求打到本地而不是 AWS，不需要 AWS 账号，用于开发机与 CI 里测试代码。它没有 GUI，启动后把 AWS CLI / 任意 SDK 的环境变量指向本地 endpoint 即可；另有 **embedded 模式**——作为 Rust dev-dependency 进程内跑，**每个测试一个隔离实例**，没有 URL、证书和环境变量可言。这个仓库 **2026 年 9 月 11 日建仓**，今日已 **5277 ⭐ / 175 forks / 314 open issues**，许可证是相当少见的 **CC0-1.0**（公有领域）。最有意思的细节是 Quick Start **第一项就是「配合 AI 编码 Agent 使用」**：`aws agent-toolkit add-skill --skill-name aws-emulator` 一条命令把模拟器装成 Agent 技能。AWS 同时在博客里谈了这对开发流程的意义。它明确写着「不要用于生产、不要用于测试安全性」，每个 release 还会发布**保真度评分（fidelity scores）**告诉你哪个服务模拟得像、哪个不像——这种「先交底再让你用」的姿态，比社区的逆向模拟器可信得多。（GitHub ⭐5.3k，CC0-1.0）

### [Muse Ember：把「每任务成本」做成主战场的最小推理模型](https://research.meta.ai/blog/muse-ember)
Meta 的 Muse 团队发布**当前最小、最高效的模型 Muse Ember**，定位非常清楚：不是陪你聊天，是干 Agent 一整天在重复的脏活——**工具调用、编码子任务、路由、抽取、长文档解析**。它的卖点不是分数而是**性价比曲线**：在 Artificial Analysis 的「智能 vs 每任务成本」图上，它落在**效率前沿**——没有任何模型能以更低的单任务成本拿到更高分。对比数据很硬：`AutomationBench-AA`（端到端业务流程）**37.8 vs Claude Haiku 5.5 的 13.9、GPT-6 Luna 的 20.2**；`Agents' Last Exam` **61.6 vs 57.0 / 57.1**；`Personal Superintelligence Index` **46.8 vs 36.1 / 37.0**。在**同等智能水平上成本约是 Haiku 的 1/3**，并且**任何一个 reasoning effort 档位都优于 Luna**。这印证了 2026 下半年的一条主线：**前沿模型的竞争正在从「最强」转向「每美元能干多少活」**，因为 Agent 工作流的 token 消耗是聊天的一百倍。（research.meta.ai，11 月 9 日）

### [Jane Street 开源 agent_skills，同时宣布面试改革：少写代码、多用 LLM](https://github.com/janestreet/agent_skills)
Jane Street 建了 `agent_skills` 仓库（**MIT，7749 ⭐，502 forks**），结构极简：每个 skill 一个目录，里面一个 `SKILL.md`。目前只放了一个 **socratic-tutor**——把 LLM 变成严格的苏格拉底式私人教师，带**诊断、0-5 级技能地图、一次只问一个问题、间隔复习、最终测评**。仓库本身很小，但它和 Jane Street 11 月 2 日那篇《**Our software engineering interviews are changing (a little)**》是一套组合拳：这家以「最难面试」著称的量化公司公开承认，**绝大多数工程师每天都在用 LLM 读代码、调试、审查**，而「**生成代码已经比以往任何时候都便宜，所以品味、抽象选择、以及确保造出来的东西真的是对的，变得更重要**」。于是今年夏天开始在校招 onsite 里试点**更少写代码、更多软件设计与代码质量审查、以及允许用 LLM 写代码**的轮次（大部分轮次仍是无 LLM 的传统编码）。这是主流大厂里少见的、把「面试该考什么」这个问题摊到桌面上讲的一次。（GitHub ⭐7.7k）

## 🔬 开源项目

### [Kimi K3.1 Pro：3T 级开源权重 + 100 万上下文，Terminal-Bench 反超 GPT-6 Astra](https://www.kimi.ai/blog/kimi-k3-1-pro)
月之暗面发布 **Kimi K3.1 Pro**，官方称其为「**迄今最强的 3T 级开源权重模型**」，**100 万 token 上下文**，代码、3D 创作、金融研究、Agent 能力全面提升；同时发布 **K3.1 Pro Highspeed**（**2-3 倍速度**）。技术路线上它是 **Kimi K3 的重度后训练版本**，为了在**数百个下游领域做大规模联合 RL**，把 RL 框架、长上下文推理、训练效率、沙箱基础设施、rollout 调度、环境质量检查平台每一层都重做了一遍，让每一份 RL 算力都有稳定可预期的回报。成绩单很能打：**Terminal-Bench 4.0 得 65.7%，超过 GPT-6 Astra 的 58.2%，仅次于 Claude Opus 5.5 的 66.4%**；内部长程基准 **Kimi Code Bench 3.0 Long-horizon 61.2%**（K3 为 55.95%）；**BenchCAD 3D 重建 92.7%（带工具）**，逼近 Opus 5.5 的 96.2%。最值得读的是那个长程案例：它让人形动力学模拟里 11.2 秒都站不住的人走起来，而且在「调奖励函数没用」时**没有继续瞎调奖励**，而是去跑模拟器的开环探针，**找出并修正了 36 处肩部肌肉力臂计算错误**再重训控制器——这种「怀疑工具而非盲目优化指标」的行为，是 Agent 长程能力真正的分水岭。（kimi.ai）

### [DeepSeek 开源 DeepInfer：把生产推理栈直接摊开](https://github.com/deepseek-ai/DeepInfer)
DeepSeek 开源了**支撑其大规模生产服务的高性能推理框架 DeepInfer**，本次放出的是**离线推理**部分，覆盖服务化所需的核心能力，**支持 DeepSeek-V4.1-Flash**。功能清单相当「工业级」：优化 kernel 与模型/采样 runtime；并行策略含 **Attention DP / 均衡 CP、MoE EP + EPLB**；**DSpark + 置信度调度的 verification**（用 draft token 加速解码，靠置信度估计安排验证，`DEEPINFER_USE_NEXTN_DECODE` 默认最大 draft 长度 5）；**SWA 有界重放**降低 decoder prefill 开销；**零开销批调度器**；**批量不变性（batch-invariant）**推理；**确定性采样**；结构化输出（regex / JSON Schema / EBNF）。全部构建在自家开源组件上——FlashMLA、DeepGEMM、DeepEP、TileKernels、DeepSelect 与 TileLang 自定义 kernel。值得注意的是「**batch-invariant + deterministic sampling**」这一组特性：这是为了让 **Agent 的评测与回归测试可以复现**，而不是服务器运维的便利——开源推理栈的竞争点已经从「吞吐」挪到了「可信赖」。（GitHub，25.9k ⭐，10 月建仓）

### [Google 开源 Harness²：不改权重，教 Agent 自己改自己的 harness](https://github.com/google-research/harness2)
Google Research 放出 **Harness²（Harness Squared）**，**23.5k ⭐ / 2.4k forks**，Apache-2.0，配套论文 arXiv 2610.14224。它想解决的是「**开放世界里 Agent 会遇到设计 harness 时没见过的任务**」这个问题，做法是**双层递归**、**完全不动模型权重**：**任务级递归**用「**Propose–Probe–Compose**」——先提出对 harness 的修改，再在同一个任务上**实测**这些修改的效果，最后依据两次执行之间的**行为对比**拼出更优 harness，全程**不需要 ground truth**；**harnessing 级递归**则把被采纳的 harness 和「有证据支撑的经验」写回一个**持久化的 improvement harness**，指导下一次精炼。装起来一行：`uv pip install -e '.[render]'`，`harness2-setup jb`，`harness2 --bench jb --k 1 --mode parallel`。它和 Kimi、Claude 那批「多 Agent 长时间跑」的工作形成有趣对照：一边是堆算力堆子 Agent，一边是**把「怎么组织 Agent」本身当成可被搜索和优化的对象**。（GitHub ⭐23.5k，Apache-2.0）

### [Cornell 研究：数据中心只付 38% 的电网扩建成本，居民承担 62%，低收入家庭能源负担高达收入 28%](https://news.cornell.edu/stories/2026/11/data-centers-need-power-lower-income-rural-residents-pay-price)
康奈尔团队在 **Nature Energy**（11 月 9 日）发表首个**多区域、长周期**的数据中心基础设施成本分配研究，覆盖美国四大电网（南旧金山湾、达拉斯-沃斯堡、中西部、以北弗吉尼亚为主的 mid-Atlantic），分析了 **4000 个现有与规划中的数据中心**、电价记录、公用事业费率申报、输电线规划与联邦家庭/就业数据。结论很直接：2025 年相关基础设施账单 **82.5 亿美元**中，**数据中心只付了 31.2 亿（38%）**，剩下 **51.3 亿（62%）落到居民头上**，**最低收入家庭多付的电费可达其收入的 28%**。传输投资从 2020 年的 **20 亿**涨到 2025 年的 **340 亿**，主要由数据中心驱动；受冲击最重的枢纽，**批发电价被推高近 10% 或更多**（弗吉尼亚 **15%**、南湾 **20%**），而建设有限的组织与英格兰地区不明显。根因是**成本分摊基于历史用电模式**——「你要建数据中心就得扩容电网，但建之前它没用电，于是按历史分摊时家庭吃了大部分成本」。回报一侧也不全是坏消息：**每 GW 数据中心容量可在全经济范围创造 1.5 万个岗位**（直接相关约 2700 个），加州每 1 美元激励换来 **180 美元**劳动者收入、弗吉尼亚是 **2 美元**，且**现成合格劳动力比激励金额更能预测高回报**。到 2030 年数据中心将吃掉美国 **8%-17%** 的电力，其中 **70%-80%** 归因于 AI。这比「AI 缺不缺电」更值得讨论：**电是有了，账单归谁**。（news.cornell.edu，Nature Energy）
